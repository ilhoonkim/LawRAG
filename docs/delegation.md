# 위임조문 관계와 현행 법령 세트 수집

## 해양·환경 법률 31개 수집

앱 서버를 종료한 뒤 프로젝트 폴더에서 실행합니다.

```powershell
git pull
.\.venv\Scripts\python.exe -m app.preload_maritime
```

기본 목록은 `app/preload_maritime.py`의 `LAWS`에 있습니다. 요청된 법률 31개와 공식 체계도의 시행령·시행규칙을 수집합니다. 하위 규칙이 여러 개면 모두 포함하며 행정규칙은 제외합니다. 법령별 **오늘 시행 중인 최신 버전 1개**만 고릅니다. 기존 `preload_real_estate`의 최근 3개 연혁 수집과 다른 명령입니다.

현재 버전은 `eflaw`, `nw=3` 현행 검색으로 확인합니다. 하위법도 체계도의 날짜만 믿지 않고 현행 검색으로 확인하며, 미래 시행·공포 버전은 제외합니다. `수상레저기구의 등록 및 검사에 관한 법령`은 `…법률`로 이름을 보완합니다. `해사안전법` 등 정확한 이름으로 현행 결과를 못 찾는 항목은 과거 버전이나 비슷한 후속 법으로 대체하지 않고 실패 사유를 남깁니다. 현행 명칭을 확인한 후 별도로 지정할 수 있습니다.

```powershell
# 대상과 날짜만 확인: 본문 다운로드/AI 호출 없음
.\.venv\Scripts\python.exe -m app.preload_maritime --list-only
# 기본 목록 외 법령명도 가능. 공식 하위법을 함께 수집
.\.venv\Scripts\python.exe -m app.preload_maritime --law "선박안전법"
# UTF-8 파일에 한 줄당 법령명 하나
.\.venv\Scripts\python.exe -m app.preload_maritime --names-file .\laws.txt
```

중단 후 같은 명령을 실행하면 DB에 완료된 본문은 건너뛰고 빠진 버전만 수집합니다. 같은 실행에서 공유 하위법은 중복 시도하지 않습니다. 메타데이터 생성·임베딩까지 마친 뒤 관계를 매핑합니다. 관계 조회 실패/버전 미확인은 본문 완료와 별도 상태이며 이를 이유로 재임베딩하지 않습니다.

세트의 본문과 관계 매핑을 마치면 **저장 HTML의 상하위 링크도 자동 생성**합니다. `data/html` 파일을 직접 열어도 `법 제N조`, `영 제N조`와 상하위 조문 연결이 같은 폴더의 대상 HTML·조문 앵커로 이동합니다. 새 수집에는 별도 리빌드 명령이 필요 없습니다. 터미널과 결과 JSON의 `html` 항목에서 생성 완료/실패 수를 확인할 수 있습니다.

`「법령 전체 이름」(이하 "법" 또는 "영"이라 한다)` 선언부의 전체 이름도 해당 문서로 연결합니다. 선언 바로 뒤의 조번호는 그 문서의 해당 조문으로 이동하며, 뒤에서 사용하는 약칭도 같은 대상을 참조합니다. 기준일에 해당 문서가 미수집이면 법령명·조번호는 원문 텍스트로 유지합니다.

`--data-dir`로 저장소를 지정할 수 있습니다. 결과는 `DATA_DIR/preload-maritime-report.json`과 앱의 수집 이력에 저장됩니다. 종료 코드: `0` 완료, `1` 일부 미완료, `2` 설정 오류, `130` 사용자 중단. 조회 전용도 체계도·계획·연혁 메타데이터는 DB에 저장합니다.

## 수집·저장 흐름

`Management.run()`이 본문 수집을 마치면 `LawAPI.delegation()`으로 가족별 한 번 다음 API를 요청합니다.

```text
lawService.do?target=thdCmp&MST=...&knd=2&type=JSON&OC=...
```

`app/delegation.py`가 `LspttnThdCmpLawXService.위임조문삼단비교.법률조문`의 시행령/시행규칙 조문을 파싱합니다. 단일 객체와 배열을 처리하고 행정규칙은 제외합니다.

| 저장 위치 | 내용 |
| --- | --- |
| `delegation_snapshots` | 요청 MST, 성공 응답 JSON 원본, 갱신 시각·상태·사유 |
| `delegation_sources` | 수집 버전과 조회한 가족 MST 연결 |
| `delegation_edges` | 양쪽 버전 해시·조번호·방향·관계 종류·출처 |
| `delegation_unresolved` | 버전을 확인하지 못한 관계 후보와 사유 |

관계 종류는 두 가지입니다.

- `delegation_comparison`: API가 제공한 법률 중심 위임조문 비교 관계. 같은 행에 있다는 이유만으로 모든 시행령×시행규칙 조합을 직접 위임으로 만들지 않습니다.
- `hierarchy_citation`: 같은 비교 묶음의 시행규칙 본문에서 실제 `영 제N조` 등으로 인용한 시행령 관계. 상위→하위 방향으로 저장하고 실제 본문 인용 방향은 하위→상위임을 출처에 기록합니다. 인용만으로 직접 위임의 법적 성격을 단정하지 않습니다.

**요청 MST는 응답 버전을 증명하지 않습니다.** 응답의 법령 식별자(제공된 경우), 시행일/공포일, 조 전체 본문과 저장 버전이 유일하게 일치해야 연결합니다. 응답에 공포일만 있고 시행일이 없으면 연혁 카탈로그로 확인한 현재 버전에만 연결하며 과거 버전에는 붙이지 않습니다. 날짜가 없거나, 본문이 다르거나, 여러 시행 버전이 일치하면 미해결로 남깁니다. 과거 MST로 요청했어도 현재 비교 결과가 오면 과거 수집본에 억지로 붙이지 않습니다. 대상 본문을 나중에 수집한 경우 저장 응답을 재매핑할 수 있습니다.

관계 조회 실패는 본문 수집 완료를 실패로 바꾸지 않습니다. 이전에 확인한 관계와 원문은 보존하고 마지막 갱신 실패를 기록합니다. 미해결 사유와 원본은 DB에서 조사할 수 있습니다.

## 검색·답변·화면

1. 원질의+rewrite로 검색하고 임계치를 통과한 상위 15개를 LLM으로 검토합니다.
2. 통과한 근거에서 상위/하위를 각각 최대 2단계 확장합니다. 위로 갔다가 옆 가지로 내려가는 형제 확장은 하지 않습니다.
3. 질문 기준일에 양쪽 버전 모두 유효한 관계만 사용합니다. 확인된 최신 버전이 미수집이면 과거 버전으로 대신 연결하지 않습니다.
4. 확장된 상하위 조문도 **최대 15개를 묶어 별도 LLM 관련성 검토**를 합니다. 전체 본문과 연결 방향·API 출처를 전달하되 위임 관계만으로 관련 있다고 판정하지 않도록 합니다. 실제 단계는 `상하위 연결 조문 검토 중`으로 표시합니다.
5. **검토를 통과한 연결 조문만** 충분성 판단·답변 LLM 및 숫자 인용 가능한 화면 출처에 포함합니다. 같은 법령별로 묶고 연결 출발 조문을 표시합니다. 연결 조문에 출발점의 점수를 자기 검색 점수처럼 표시하지 않고 `상하위 연결 근거`로 구분합니다. 미해결 상대 조문은 부족한 자료 목록으로 전달합니다.

조문 수/본문 길이 예산은 유지합니다. 조문 중간을 자르지 않고 예산 때문에 제외한 자료는 누락 목록에 남깁니다. 검토는 개별 조문별 순차 호출이 아니라 묶음 호출이며, 긴 입력은 최대 두 묶음 병렬 처리합니다. 같은 요청의 추가 검색에서는 이미 판정한 법령·버전·조문의 결과를 재사용합니다. 탈락한 후보는 검색·연결 경로로 다시 추가하지 않습니다. 상하위 자료는 `include_in_sources=true`를 사용하며 일반 정의·별표·참조 문맥은 종전처럼 LLM 전용일 수 있습니다.

HTML 본문의 `법`, `영`은 약칭 선언/공식 상위 체계와 기준일을 이용해 저장된 상대 HTML로 이동합니다. 각 조 아래 **상하위 조문 연결**에서도 확인된 상위/하위 문서를 양방향으로 엽니다. 앱의 `/documents/` 응답은 질문 기준일의 대상 버전과 `as_of` 날짜, 조문 앵커를 포함합니다. 정적 파일은 생성 당시의 기준일(현행은 오늘, 과거는 해당 버전 시행일)을 문서 상단에 표시하고 상대 파일명으로 연결합니다. 파일로 전달할 때에는 연결 대상 HTML도 같은 폴더에 함께 복사해야 합니다. 열람 중 API/AI 호출이나 재임베딩은 없습니다.

## 기존 자료의 관계만 보완

이미 상하위 본문을 수집했다면 재임베딩 없이 관계만 보완할 수 있습니다. `LAW_API_OC`와 3단비교 이용 권한이 필요하며 AI 키는 필요 없습니다.

```powershell
.\.venv\Scripts\python.exe -m app.backfill_delegation
# 완료된 원격 응답까지 다시 조회
.\.venv\Scripts\python.exe -m app.backfill_delegation --refresh
```

`--law`, `--data-dir`를 지원합니다. 결과는 `delegation-backfill-report.json`과 DB에 저장합니다. 완료된 API 응답은 기본 재사용하며 실패/미확인 관계는 재시도합니다. 상하위 본문 자체가 없다면 `app.backfill_hierarchy` 또는 새 현행 세트 수집 명령으로 먼저 수집하세요.

실제 API 응답은 로컬 OC 환경에서 검증해야 합니다. 자동 테스트는 합성 응답으로 버전 불일치·누락·양방향 탐색·출처 인용·HTML 이동·중단 후 재개를 검증합니다. 위임 API의 제공 범위를 넘는 부칙/경과조치의 적용 판단은 자동으로 확정하지 않습니다.
