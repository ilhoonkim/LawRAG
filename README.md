# LawRAG

Python/FastAPI 백엔드와 React/Vite 프론트엔드로 구성한 로컬 법령 RAG 앱입니다. 왼쪽 메뉴는 **법령관리 / 채팅**으로 분리합니다. React 빌드 결과를 저장소에 포함하므로 실행만 할 때는 Node.js 설치 없이 Python 서버 하나로 사용할 수 있습니다.

## Windows 로컬 실행 및 업데이트

PowerShell에서 실행합니다. 기존 서버는 해당 창에서 `Ctrl+C`로 종료한 뒤 업데이트하세요.

```powershell
cd "C:\Users\김일훈\local_dev\LawRAG"
git pull --ff-only origin main
# 최초 설치 때만 가상환경을 생성합니다.
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

브라우저에서 `http://127.0.0.1:8001`을 엽니다. 이미 설치했다면 pull 후 서버 재시작만으로 화면 변경이 반영됩니다. `.env`와 `data/`는 Git에서 제외하므로 로컬 키·수집 자료가 유지됩니다. Linux/macOS에서는 `.venv/bin/python`을 사용합니다.

Python 3.12, SQLite 확장 로드가 가능한 환경이 필요합니다. 수집 실행기는 단일 서버 프로세스를 전제로 합니다. 여러 `--workers`로 실행하지 마세요. 인증 없는 로컬 개발 앱이므로 공개 배포 전에는 인증·호출량 제한 등을 추가해야 합니다.

## 환경 변수

`.env` 또는 프로세스 환경 변수로 설정합니다. 이미 주입된 값이 `.env`보다 우선하며 변경 후 서버를 재시작합니다. 키를 채팅이나 Git에 올리지 마세요.

| 변수 | 용도 / 기본값 |
|---|---|
| `LAW_API_OC` | 국가법령정보 공동활용 OC 식별값. 법령 및 사용하는 행정규칙 API 권한 필요 |
| `LLM_API_KEY` | OpenAI API 키. 미설정이면 기존 `OPENAI_API_KEY` 사용 |
| `LLM_BASE_URL` | `https://api.openai.com/v1`, embeddings/chat completions 호환 서버 |
| `EMBEDDING_MODEL` | `text-embedding-3-small` |
| `CHAT_MODEL` | `gpt-4.1-mini` |
| `SEARCH_THRESHOLD` | 최종 근거 점수 하한, `0.48` |
| `SEARCH_TITLE_WEIGHT` | 제목 점수 비중 `0.35`, 본문 비중은 `1 - 이 값` |
| `SEARCH_MIN_TITLE_SCORE` | 제목 점수 하한 `0.15` |
| `SEARCH_MIN_BODY_SCORE` | 본문 점수 하한 `0.20` |
| `DATA_DIR` | 기본 프로젝트 `data/` |

실제 연동에는 HTTPS `www.law.go.kr`, `api.openai.com` 접근이 필요합니다. 이 클라우드에서는 프록시 403으로 실제 연동을 검증하지 못했습니다. 사용자 PC의 허용 IP 및 API 권한을 기준으로 별도 검증해야 합니다.

## 법령관리

사용자가 지정한 [부동산 관련 26개 목록](docs/real_estate_catalog.md)을 카테고리에 한 번 등록합니다. 본문은 자동 수집하지 않습니다. 카테고리 추가 버튼은 없으며 새 법령 수집 완료 시 목록에 자동으로 추가합니다. 화면 진입은 수집을 실행하지 않습니다.

**지정 목록 일괄 수집:** 상단 **부동산 지정 목록 · 26** → **26개 조회·수집 시작**. 로컬 `.env`의 OC와 AI 키를 사용해 각 명칭의 연혁을 조회하고, 시행일이 오늘 이하인 최신 1개 버전을 수집합니다. 이미 수집된 버전은 건너뜁니다. 목록의 명칭은 바꾸지 않으며 과거 명칭·미수록 지침은 실패 사유 또는 비고를 확인하세요. 전체 연혁 수집은 아래 개별 수집 화면에서 선택합니다.

1. **수집하기**를 누릅니다.
2. 법령명과 구분을 입력하고 **검색**합니다.
3. 검색 결과의 법령명 **버전 조회**를 누릅니다.
4. 현재 페이지의 **미수집 버전만 자동 체크**됩니다. 완료 또는 대기·실행 중인 항목은 제외합니다. 필요한 항목만 남길 수 있습니다. 페이지 변경 시 선택은 초기화됩니다.
5. **수집 시작**을 눌렀을 때만 API 본문 다운로드와 임베딩을 실행합니다. 제목·본문 임베딩까지 성공해야 수집 완료로 표시합니다. OC 또는 AI 키가 없으면 수집 시작 전에 설정 오류를 안내합니다.
6. **수집 이력**에서 완료·실패·대기·실행·중단 상태와 실패 사유를 확인합니다. 완료한 버전은 서버에서도 중복 수집을 차단하며 실패한 항목은 재시도할 수 있습니다.
7. 수집된 개정 연혁에서 법령명을 누르면 하단에 조문 목록이 표시됩니다. 조문 버튼은 버전별 HTML의 해당 조로 이동하는 팝업을 엽니다.

API 이름 검색은 관련 법령도 반환할 수 있습니다. 버전 조회는 현행·연혁·시행예정 조회 결과를 버전 식별자로 합치고, 선택한 정확한 법령명(공백 차이 제외)으로 필터링한 뒤 건수·페이지를 계산합니다. 이름 검색 결과에 섞인 시행령·시행규칙은 해당 법률의 개정 건수에 포함하지 않습니다. 원격 연혁은 60초 동안 캐시하며 일부 페이지가 누락되거나 반복되면 오류로 표시합니다. API에서 제공하는 공포/발령·시행일을 표시하며 임의의 개정일을 만들지 않습니다. 현재 수집/목록/이력 페이지 크기는 10건입니다.

기존 단일 벡터 색인 또는 키워드 전용 자료는 **버전 상세 → 제목·본문 재색인**으로 업그레이드할 수 있습니다. 저장된 XML을 사용하며 AI API 비용이 발생합니다. 원본이 없으면 재색인을 중단합니다.

## 시점별 검색

- 기본은 한국 시간의 오늘까지 시행된 **수집 버전 중 가장 최신**입니다. 시행 예정 버전을 현재 법으로 사용하지 않습니다.
- `2020년 6월 1일 기준 …`, `2020-06-01 기준 …` 질문이나 `/api/search`, `/api/chat`의 `as_of` 날짜로 해당 시점의 버전을 선택합니다.
- 연도만 지정하거나 기간·당시 같은 표현은 날짜를 다시 묻습니다. 기간 전체의 모든 개정 비교 및 대화 맥락에서 날짜 추론은 아직 하지 않습니다.
- API에서 확인한 적용 버전이 미수집이면 오래된 버전으로 대신 답하지 않습니다.
- API에서 **조회한 페이지와 저장된 버전만** 알고 있으므로 모든 개정의 수집 완료나 전국 법령의 최신성을 보증하지 않습니다. 폐지·경과조치·소급적용·조문별 별도 시행일 판단, 법령명 변경에 따른 계보 통합은 별도 확장이 필요합니다.

## 제목·본문 검색 점수

조문마다 두 임베딩을 별도로 저장합니다.

- 제목 입력: `법령명 - 제N조(조 제목)`
- 본문 입력: 조 내용. API 본문에 반복된 선두 조 제목은 제거하여 제목 점수가 이중 반영되지 않도록 합니다.

각 점수는 `0.65 × 코사인 유사도 + 0.35 × 키워드 점수`입니다. 최종 점수는 `0.35 × 제목 점수 + 0.65 × 본문 점수`입니다. 키워드 전용 모드는 각 키워드 점수만 사용합니다. 제목과 본문의 최소 점수를 모두 통과한 뒤 최종 임계치를 넘는 조문만 반환합니다. 키워드는 한국어 문자 2-gram이며 적용 제외 표현을 적용범위 검색어로 확장합니다.

API 결과는 `title_score`, `body_score`, 두 키워드 점수, 두 임베딩 점수, 최종 `score`를 분리합니다. UI 출처 카드에도 제목·본문·최종 점수를 표시합니다. 가중치와 임계치는 실제 질의 평가로 조정해야 하며 확률이나 법률 정확도 수치가 아닙니다. 질문에 명시한 법령명은 가장 길게 일치하는 이름으로 제한합니다. 다중 법령 비교 검색은 별도 확장이 필요합니다.

## 참조 조문·별표 연결

SQLite에 `article_references` 관계와 `annex_nodes` 노드를 저장합니다. 외부 Graph DB 없이 **같은 개정 버전의 조문 → 참조 조문 / 별표**를 탐색합니다.

- 검색된 조문에 `제11조`가 있으면 같은 버전의 `제11조(허가구역 내 토지거래에 대한 허가)` 제목과 본문을 별도 근거로 LLM에 전달합니다. 원문 데이터는 유지하고 HTML 표시에서 제목·앵커를 보강합니다.
- `별표 2`도 같은 버전의 텍스트 본문을 별도 근거로 추가합니다. 채팅에는 각 근거의 출처 버튼이 표시됩니다.
- 현재는 직접 참조 1단계이며 재귀적 다단계 법령 추론은 하지 않습니다. 다른 법령이나 ‘같은 법’의 대상이 불명확하면 현재 법령과 임의로 연결하지 않습니다.
- API가 제공한 **일반 텍스트 별표**는 연결됩니다. PDF/HWP/이미지/복잡한 HTML 표의 다운로드·OCR·표 추출은 아직 구현하지 않았습니다. 첨부 링크와 메타데이터는 보존하지만 파일 URL을 내용처럼 취급하지 않습니다.
- 필요한 참조 본문이 없으면 미확보 근거를 알리고 LLM 답변을 생성하지 않습니다. 번호 생략형·복잡한 교차 참조는 실제 데이터에 맞춰 추가 파싱이 필요합니다.

법령 본문은 조·항·호·목의 개행을 보존합니다. 행정규칙은 구조화된 조문 XML만 지원하며 조 단위로 구분할 수 없는 형식은 실패 이력으로 보고합니다. 원문에 없는 수식·별표 내용을 생성하지 않습니다.

UI는 로컬에 포함한 Noto Sans KR 가변 글꼴과 SVG 말풍선·법령 아이콘을 사용합니다. 외부 폰트 CDN을 호출하지 않습니다. 글꼴 라이선스는 `frontend/licenses/NotoSansKR-OFL.txt`에 포함합니다.

## 프론트엔드 개발

React 소스는 `frontend/src/`, 빌드 결과는 `app/static/`입니다. **빌드 결과를 직접 수정하지 마세요.** Node.js 22 LTS 이상을 권장합니다.

```powershell
cd frontend
npm ci
npm run build
```

빌드 후 Python 서버가 결과를 제공합니다. 프론트 개발 서버가 필요하면 `npm run dev`를 사용합니다. `/api`, `/documents`는 로컬 Python 8001로 프록시됩니다. 프론트 개발 포트의 POST도 동일 출처 검사에 통과하도록 Vite의 기본 원본 Host 전달을 유지합니다. 별도 배포 시 출처 정책을 점검하세요.

## 저장 구조

- `data/raw/<해시>.xml`: API 원본
- `data/html/<해시>.html`: 버전별 HTML. `법령명-제N조`, `법령명-별표N` 앵커
- `data/laws.sqlite3`: 카테고리, 개정 버전, 제목/본문 벡터, 참조 관계, 수집 작업 이력
- sqlite-vec 코사인 거리로 정확 검색합니다. 대규모 ANN 전용 DB는 아닙니다.
- 기존 DB는 추가 테이블/컬럼으로 마이그레이션합니다. 과거 HTML·조문을 삭제하지 않습니다. 구형 색인은 재색인 전 키워드 검색만 가능합니다.
- 대화는 현재 브라우저 localStorage에 저장됩니다. 서버에 채팅 이력을 저장하지 않습니다.

## 검증

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
npm --prefix frontend run build
```

테스트 데이터와 임베딩은 합성 테스트용이며 실제 법령·모델 품질 검증이 아닙니다. 단위/API 테스트는 수집 상태·버전 분리·날짜 경계·미수집 거절·참조 연결·제목/본문 점수·마이그레이션을 확인합니다. 브라우저 테스트 서버도 임시 DB와 가짜 API를 사용해 실제 수집 비용 없이 동작합니다.

```powershell
# 선택: 브라우저 회귀 검사
.\.venv\Scripts\python.exe -m pip install playwright
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe tests/ui_smoke.py
```

실제 OC/키는 로컬 `.env`에 입력하고, 사용자가 지정한 대상에 대해서만 실제 수집·검색 품질을 검증하세요. 현재 코드는 API 응답·실제 별표 파일을 아직 직접 검증하지 못한 개발 구현입니다.
